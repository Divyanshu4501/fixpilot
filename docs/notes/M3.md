## How the loop works now

```
history = [user: issue]
repeat (until submit / 30 steps / $0.50):
    response = responses.create(instructions=SYSTEM_PROMPT, input=history, tools=[bash, submit], ...)
    history += every item in response.output     # reasoning (encrypted), text, function_call
    if there is a function_call:
        run it in the sandbox
        history += function_call_output(call_id, observation)
    else:
        history += user: "You did not call a tool..."   # the nudge; still counts as a step
patch = git diff <base commit>   # taken even if a limit was hit
```

Key terms:
- **Responses API**: OpenAI's newer endpoint. Its output is a list of *items* (`reasoning`, `message`, `function_call`) instead of one assistant message.
- **Reasoning item**: the model's hidden thinking. With `store=False` we get it **encrypted**: we can't read it, but we can send it back so the model remembers what it was thinking.
- **`call_id`**: links a `function_call` to its `function_call_output`. Every call must be answered, or the next request fails.
- **Prompt caching**: if the start of a request is identical to a recent one, those tokens are billed at the cached rate (0.01 vs 0.125 per 1M). Keeping `instructions` fixed and the history append-only keeps the start of each request identical.
- **`strict: True`**: the API guarantees the tool arguments match the JSON schema. That requires listing every property in `required` and setting `additionalProperties: false`.

Important lines in `run_agent`:
- ~~`include=["reasoning.encrypted_content"]`~~ (corrected 2026-10-23): I first thought this was needed. It isn't: with `store=False`, reasoning items already contain `encrypted_content`. The flag was removed (D2).
- `item.model_dump(exclude_none=True)`: turns the SDK's Python objects back into plain dicts for the next request (D3).
- `if response.status == "incomplete" or not calls:` → nudge. Any calls in a cut-off response still get a "Not executed" output (D4).
- `step_cost` now reads `input_tokens`, `input_tokens_details.cached_tokens`, `output_tokens`, `output_tokens_details.reasoning_tokens`. Reasoning tokens are already included in `output_tokens`, so they're not added twice.

## What surprised me
- **Very little reasoning:** 95 reasoning tokens in total at `medium`. On an easy task, `gpt-6-luna` barely thinks. Effort may matter more on harder tasks; that's an ablation, not something one task can show.
- **Caching only kicked in at step 4.** The cached prefix appeared once the prompt was ~1.7k tokens long. Below that (steps 1–3), nothing was cached. Small prompts gain little from caching. Long trajectories gain a lot.
- **The model packs several actions into one command** (edit + repro + tests in step 3, joined by heredocs). That saves steps, but one failing piece makes the whole command exit non-zero. Here the edit and repro worked and only the test path was wrong. Keep an eye on this in failure analysis.
- The step-3 failure was the **fresh-shell rule** in action: `runtests.py` lives in `tests/`, and the model fixed it right away.
- The model ran the existing tests (2 tests), not the hidden `FAIL_TO_PASS` ones. It never saw those, as intended (no leakage).
